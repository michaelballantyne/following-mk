# Cutover design: deleting the closure engine (backlog 3b, second half)

Design note for the second half of 3b, per Michael's go-ahead after the
benchmark-parity result (`...-073254-residual-engine-benchmark-parity.md`).
Read alongside `2026-07-13-051843-residual-goals-design.md` (the original
representation design) and `residual.scm`'s header. This note makes the
execution decisions the migration plan left open at port time — tally/d's
residual form, the follower/trigger rewrite, and exactly what gets deleted
vs. edited-in-place vs. renamed — before handing off implementation.

## The key realization: edit in place, don't swap files

The mechanical-port phase (necessarily, for coexistence) wrote parallel
`-res`/`r`-prefixed files: `residual-views.scm`, `residual-interp-
following.scm`, `residual-interp-untyped-following.scm`. The obvious-looking
cutover move is "delete `views.scm`, rename `residual-views.scm` ->
`views.scm`" (and likewise for the interpreters). **This is wrong and would
silently destroy test coverage**: `views.scm` has 47 inline self-check
`test` forms (the house style: "the inline (test ...) forms are the view
self-checks; they run at load time and count in the suite"); the
differential port only sampled 19 of them into a separate test file, because
during coexistence the *closure* originals already covered the rest. Delete
`views.scm` and that coverage is gone with it, silently.

The fix: once names are canonical, a residual relation's `conde/d` clauses
are **textually identical** to the closure version's — both already use the
same `((x ...) (g ...) (b ...))` clause shape. The *only* required
syntactic change to port a views.scm relation is: recursive `(define (foo
...) (conde/d ...))` becomes `(define-relation/d (foo ...) (conde/d ...))`
(the g-call laziness requirement is permanent, not migration scaffolding).
Non-recursive helpers need no change at all. So: **edit `views.scm`,
`restricted-interp-following.scm`, `restricted-interp-untyped-following.scm`
in place** — convert `define` to `define-relation/d` on recursive relations,
keep every comment, every test, every non-recursive helper untouched — then
delete the now-superseded staging files (`residual-views.scm`,
`residual-interp-following.scm`, `residual-interp-untyped-following.scm`);
their job (prove the port works) is done.

R2T (`terminating-recursiono/d`/`concluding-oro/d`) cannot be edited this
way — it's written directly against `inf/d`/`case-inf/d`, which are being
deleted. Its **code and its gate tests must be removed** from `views.scm`
(they'd reference deleted primitives). Its **comments** (the non-viable
analysis, the soundness argument for R2 OR R2P) should be preserved,
demoted to documentation only — pointer to
`2026-07-13-040000-r2p-r2t-termination-generalization.md`, note that
rescuing it is backlog 3c's open research question.

## following.scm: what deletes, what stays, what gets rewritten

**Delete** (closure-engine-only, confirmed by direct inspection):
`hard-suspended` (record), `inf/d?`, `case-inf/d` (macro), `check-unsound-
fail-depth`, `check-suspend-depth`, the closure `conde/d` macro +
`conde/d-runtime`, `conj/d-run`, `conj/d-resume`, `conj/d*`, the closure
`fresh/d` macro, `succeed/d`, `wrap-for-depth-limit`, and the six primitive
constructors built from it: `==/d`, `=/=/d`, `absento/d`, `symbolo/d`,
`numbero/d`, `stringo/d`. Also `*unsound-fail-depth*` and
`*unsound-fail-depth-cutoff-counter*`: `settle` never threads
unsound-fail-depth at all (confirmed — it doesn't appear anywhere in
`residual.scm`) and every differential test passed regardless, which is
consistent with BACKLOG.md's existing Later/ideas note that this parameter
is "still unused" and a removal candidate. Deleting it here resolves that
backlog item too, as a side effect — note it in the follow-up entry.

**Stays unchanged**: `follower`/`follower-aux` (rewritten, see below, not
deleted), `state-F`/`state-with-F` and the rest of the mk state accessors,
`*suspend-depth*` (settle already reads this directly), `*main-unsound-
depth*` (a completely separate leader-side knob, orthogonal to the
follower engine), all the counters (`*fail-counter*`,
`*singleton-succeed-counter*`, `*non-singleton-succeed-counter*`,
`*conde/d-counter*`, `*suspend-depth-cutoff-counter*`, etc.) and their
reset/print machinery, `*view-tally-alist*`/`view-tally-ref`/`reset-view-
tallies!`/`view-tally-bump!`/`view-store-changed?`/`print-view-tallies`
(engine-agnostic bookkeeping), `record-depth-entry!`/`record-depth-cutoff!`
and the productivity-tally machinery, `tally-productivity!`, `reify-for-
tally`. `==-counted` (the raw counted-unify wrapper, NOT the closure `==/d`
built from it) stays — `residual.scm`'s `r==/d` already calls it directly,
confirming it's engine-agnostic.

**Rewrite**: `follower-aux`, `run-and-set-follower`, `trigger-followers`.
Today these speak the 4-way `inf/d` protocol (`#f` / singleton state /
`(state . thunk)` / `hard-suspended`) because `residual.scm`'s
`follower-residual-goal`/`settle->inf/d`/`residual-resume` exist *purely* to
translate a residual Goal into that protocol so it could plug into the
unchanged closure-engine follower machinery during coexistence. Post-cutover
there is no other protocol to speak, so that whole translation shim is
dead weight. The clean rewrite:

```scheme
;; state-F now holds (residual-goal . term) instead of ((suspend-depth ->
;; st -> inf/d) . term) -- a plain data Goal node, not a curried closure.
(define (follower-aux t g)
  (lambda (st) (run-and-set-follower (cons g t) st)))

(define (run-and-set-follower F st)
  (let ([g (car F)] [t (cdr F)]
        [before-reified (reify-for-tally (cdr F) st)])
    (set! *in-follower-eval?* #t)
    (let ([result
           (let ([r (settle g (state-with-scope st (new-scope)) 0)])
             (cond
               [(not r) (increment-counter! *fail-counter*) #f]
               [(g-top? (car r))
                (increment-counter! *singleton-succeed-counter*)
                (tally-productivity! before-reified t (cdr r))
                (state-with-F (cdr r) #f)]
               [else
                (increment-counter! *non-singleton-succeed-counter*)
                (tally-productivity! before-reified t (cdr r))
                (assert-flat-residual! (car r)) ; checked invariant, was
                                                 ; already wired at the
                                                 ; settle->inf/d boundary
                (state-with-F (cdr r) (cons (car r) t))]))])
      (set! *in-follower-eval?* #f)
      result)))
```

`trigger-followers` is unchanged in shape (still reads `state-F`, calls
`run-and-set-follower` if non-#f) since `F`'s *shape* (`(goal . term)`) is
preserved, only what `goal` *is* changes. Delete `follower-residual-goal`,
`settle->inf/d`, `residual-resume` from `residual.scm` once this lands —
their sole purpose was bridging to the code being deleted here.

## tally/d: the residual form (the one real design decision, not just a rename)

No residual analogue exists yet — flagged as an open question at port time
("Tally placement: label field on every node vs a thin g-spy wrapper node.
Decide at port time.") Cutover *is* port time, and following.scm's `tally/d`
currently hard-depends on `case-inf/d`/`hard-suspended` internals being
deleted this same pass, so this can't be deferred — the build won't load
without it.

Decision: a new **wrapper node**, `g-tally` (thin wrapper, not a label
field on every node — keeps the core datatype's closed set undisturbed and
matches how rarely tally/d is actually used: only in benchmark arms, never
in the core engine or the interpreter).

```scheme
(define-record-type g-tally (fields label goal))
```

`settle` gets one more dispatch case, `[(g-tally? g) (settle-tally g st
depth)]`, mirroring `tally-step`'s exact semantics (refute/force via a
before/after store-identity comparison) but adapted to settle's `#f |
(cons residual state)` protocol instead of `inf/d`:

```scheme
(define (settle-tally g st depth)
  (let ([label (g-tally-label g)]
        [entry-M (subst-map (state-S st))]
        [entry-C (state-C st)])
    (let ([r (settle (g-tally-goal g) st depth)])
      (cond
        [(not r) (view-tally-bump! label 'refute) #f]
        [else
         (when (view-store-changed? (cdr r) entry-M entry-C)
           (view-tally-bump! label 'force))
         (if (g-top? (car r))
             r
             (cons (make-g-conj
                    (map (lambda (c) (make-g-tally label c))
                         (g-conj-goals (car r))))
                   (cdr r)))]))))

(define (tally/d label goal) (make-g-tally label goal))
```

**The one subtlety that must not be skipped, and why**: do NOT wrap the
*whole* residual pool from `(car r)` in a single `g-tally` node. The
residual is always a flat `g-conj` that can mix store-blocked (`g-disj`,
soft) and budget-blocked (`g-blocked`, hard) conjuncts. `partition-blocked`
(in `settle-conj`) uses `g-blocked?` to decide which pool a conjunct goes
into, and the whole point of that split — the fix for finding 1 in the
engine review — is that hard conjuncts must NOT be re-swept on every store
change within a pass. A single `g-tally` wrapping the entire pool would
read as one opaque non-`g-blocked?` node, get classified soft, and get
re-settled (hence re-expanding its hidden `g-blocked` children) on every
store change: **the exact exponential commit-splice bug relocated inside
the tally wrapper.** Wrapping *each surviving conjunct individually* in its
own same-labeled `g-tally` preserves each conjunct's true nature underneath
the wrapper. `partition-blocked` needs one more clause to see through it:

```scheme
(define (tally-blocked? node)
  (and (g-tally? node)
       (or (g-blocked? (g-tally-goal node))
           (tally-blocked? (g-tally-goal node)))))
;; in partition-blocked's classification: hard iff (g-blocked? node) or
;; (tally-blocked? node); else soft.
```

**Required regression test** (do not skip): a tally/d-wrapped diverging
guard scenario, the same shape as the engine review's
`probe-blocked-guard-commit.scm`/finding 1 and its
`tests/residual-guards.scm` witness test, but with the guard's `diverge/d`
wrapped in `(tally/d 'SOMELABEL ...)`. Assert BOTH the correct decision
vector (matches the un-wrapped case) AND a bounded, non-exponential
`*suspend-depth-cutoff-counter*` — this is the test that would have caught
finding 1 had tally/d existed then, and is exactly the class of bug this
design is guarding against. Add it to `tests/guard-robustness.scm` or a
new small file; either is fine.

## Test suite restructuring

Every `tests/residual-*.scm` file exists to compare the residual engine
against the closure engine on the same scenario. Once there is only one
engine, that comparison is meaningless (both sides call the same code) —
these files should be **deleted**, not converted, *except* where they hold
content with no other home:

- `tests/residual-decisions.scm`: 100% differential, delete. Its scenarios
  were explicitly built as ports of scenarios already in
  `refutation.scm`/`following-interpreter.scm`/`guard-robustness.scm` —
  those keep running (unchanged file content) against the residual engine
  under canonical names, so nothing is lost.
- `tests/residual-engine.scm`: Part 1 (core /d control) and Part 2 (R1
  gates) duplicate `determinacy-goal-forms.scm` and `views.scm`'s own R1
  self-checks respectively — delete both parts. **Part 3 (direct
  `settle`-level shape tests: TOP+extension on commit, flat-residual +
  `assert-flat-residual!` + `residual->sexp` on nondet, `g-blocked` on
  budget exhaustion) has no duplicate anywhere else — salvage it**, renamed
  to canonical calls, into a new `tests/engine-shape.scm`.
- `tests/residual-interp.scm`: 100% differential (both interpreters' gates
  already live in `following-interpreter.scm`/`refutation.scm`), delete.
- `tests/residual-guards.scm`: the 8 ported guard-robustness scenarios and
  the two decision-equiv variants duplicate `tests/guard-robustness.scm`
  (which keeps running against canonical names) — delete those. **The
  pruning-witness test (finding 3's one-sided cutoff exception) documents a
  real, permanent property of the (only, now) engine — convert it to a
  single-engine assertion** (drop the closure-side comparison, keep the
  residual vector as a direct hard-coded expectation) and fold it into
  `tests/guard-robustness.scm` as a new case describing pruning as
  present-day behavior, not a residual-vs-closure quirk.
- `tests/residual-views.scm`: entirely duplicates `views.scm`'s own inline
  self-checks (which keep running) — delete entirely.
- `tests/residual-untyped-interp.scm`: entirely duplicates
  `tests/untyped-interp.scm`'s gates (which keep running, including gate
  4(d) since `views.scm`'s R1/R2 will be available under canonical names)
  — delete entirely.

Net effect: `test-all.scm` shrinks back down to close to its pre-migration
shape, plus the salvaged `tests/engine-shape.scm` and the pruning case in
`tests/guard-robustness.scm`, plus the new tally/g-tally regression test.
Target `test-all.scm`:

```scheme
(load "load.scm")
(load "restricted-interp.scm")
(load "restricted-interp-following.scm")       ; now the (only) residual impl
(load "restricted-interp-untyped.scm")
(load "restricted-interp-untyped-following.scm") ; now the (only) residual impl

(load "tests/determinacy-goal-forms.scm")
(load "tests/guard-robustness.scm")            ; + pruning case, + tally/g-tally case
(load "tests/following-interpreter.scm")
(load "tests/refutation.scm")
(load "tests/leading-following.scm")
(load "tests/untyped-interp.scm")              ; loads views.scm (now residual impl)
(load "tests/view-tallies.scm")
(load "tests/engine-shape.scm")                ; salvaged direct-settle tests

(test-summary)
(when test-failed (exit 1))
```

## Benchmark re-baseline

The 20 `experiments/*-residual.scm` files from the comparison phase are now
redundant duplicates: the *original* experiment files (`*-full-id-views.scm`,
`*-untyped-id-ty.scm`) call `views.scm`'s relations by canonical name, which
now *is* the residual implementation — they run on the residual engine
automatically, no changes needed. Delete all 20 `-residual.scm` files (their
comparison job is done and recorded in the parity notebook entry). Re-run a
representative sample of the ORIGINAL files post-cutover and confirm they
reproduce the *already-recorded residual* numbers from the parity entry
(not the old closure numbers) — this is the sanity check that renaming
didn't silently change behavior. Full re-run of all 20 is better than a
sample if time allows, but a sample (say, rember typed + rember-untyped +
one R2P arm + confirmation that the interleave no-R2 arm still times out at
the same bound) is the minimum bar.

No new counters are needed for the "bridging table" the original migration
plan anticipated (settle passes / expansions / commits / alt deaths / stamp
hits) — the existing counters (`unify-main`, `conde-main`, `unify-follower`,
`conde/d`, etc.) already carry the same names and semantics through
`settle`, confirmed by the whole decision-equivalence and benchmark-parity
effort this session. There is nothing to bridge. New counters are future
work, tied to when the stamp fast path (still not implemented, per
`residual.scm`'s header) actually lands.

## Sequencing and verification bar

One indivisible change (following.scm, residual.scm, views.scm, both
interpreters, and test-all.scm all move together — the build doesn't load
in any intermediate state). Execute in this order so a mid-way failure is
easy to localize:

1. Rewrite `following.scm`: delete the closure engine + primitives listed
   above, rewrite `follower-aux`/`run-and-set-follower` to call `settle`
   directly, add nothing else yet (tally/d still broken at this point,
   expected).
2. Rewrite `residual.scm`: rename every `r`-prefixed surface constructor to
   canonical (`rconde/d`->`conde/d`, `rfresh/d`->`fresh/d`, `r==/d`->`==/d`,
   `r=/=/d`->`=/=/d`, `rabsento/d`->`absento/d`, `rsymbolo/d`->`symbolo/d`,
   `rnumbero/d`->`numbero/d`, `rstringo/d`->`stringo/d`, `rsucceed/d`-
   >`succeed/d`, `rfail/d`->`fail/d`); delete `follower-residual-goal`,
   `settle->inf/d`, `residual-resume` (superseded by step 1's rewrite); add
   `g-tally` + `settle-tally` + the `partition-blocked` extension + `tally/d`
   per the design above; update the header comment (no more "coexists with
   the closure engine" framing — this is now simply the engine).
3. Edit `views.scm` in place: recursive `define` -> `define-relation/d`
   throughout R1/R2/R2P/TY/NV, remove R2T's code (keep its comments,
   demoted to documentation, pointing at the existing non-viable-negative
   notebook entry and backlog 3c). Keep every existing test.
4. Edit `restricted-interp-following.scm` and
   `restricted-interp-untyped-following.scm` in place the same way.
5. Delete the staging files: `residual-views.scm`,
   `residual-interp-following.scm`, `residual-interp-untyped-following.scm`.
6. Restructure the test suite per the plan above; get `test-all.scm` fully
   green, including the new tally/g-tally regression test and the pruning
   case.
7. Delete the 20 `experiments/*-residual.scm` files; re-run a representative
   sample of the originals and confirm numbers match the parity entry's
   already-recorded residual figures.

Verification bar: `./run.sh test-all.scm` green start to finish (expect
somewhere near the pre-migration 171 plus a handful of salvaged/new tests —
NOT 213, since the differential files are gone); the benchmark sample
reproduces recorded numbers; `git grep` for `rconde/d\|r==/d\|r=/=/d\|
rabsento/d\|rsymbolo/d\|rnumbero/d\|rstringo/d\|rsucceed/d\|rfail/d\|
follower-residual-goal\|inf/d\|case-inf/d\|hard-suspended\|conj/d-run\|
conj/d-resume` across the whole tree returns nothing (confirms no stray
references to deleted/renamed machinery survive anywhere, including
`experiments/`, `synthesis/`, and any file not touched by the steps above).
